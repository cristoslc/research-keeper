# Retro: v1.16.0 Release

## Summary

Released v1.16.0 with `import-rk` command and `import-trove` manifest validation, page screenshots and component installer. Three friction points surfaced: stale backup directories generating security scan noise, a transitive DoS vulnerability requiring a pre-release patch, and a squash-merge conflict that reintroduced dropped dependencies on the release branch.

## Reflection

### What went well

The README gate caught two stale claims before release ("images" content type and deprecated `--content` flag). Both were trivial fixes (one-line edits) but would have misled users on first use. Evidence the gate adds real value.

Security cleanup was targeted and decisive — `rm -rf` across 8 paths eliminated 21 false critical findings in one pass.

### What was surprising

**Release branch reverted dependency removals.** The squash-merge from trunk into `release` hit conflicts on `pyproject.toml`, `uv.lock`, `CHANGELOG.md`, `cli.py`, and `templates/skill.md`. Resolving all with `--ours` kept the release branch's `pyproject.toml` — which was from v1.14.0 and still listed `sentence-transformers`, `torch`, and `transformers`. Those were removed in v1.15.0 but the release branch never got the update.

`uv tool upgrade` (the standard install path) pulls from the release branch, so every user who upgraded during that window would get ~10 GB of unnecessary ML dependencies. Caught by operator observation of the upgrade output.

**Twisted patched version is pre-release only.** The DoS in `twisted.names` (GHSA-grgv-6hw6-v9g4) is patched in `26.4.0rc2` but there is no stable release. Required a `[tool.uv] constraint-dependencies` pin in pyproject.toml to force the resolver past its pre-release skip.

### What would change

**Squash-merge conflict resolution needs file-type awareness.** `pyproject.toml` and `uv.lock` should always come from trunk — they define the version and dependency set being released. The rule is now in AGENTS.md but it's human/agent memory, not enforcement. An automated check ("do release branch deps match trunk?" post-merge) would close the gap.

**Pre-release cleanup should happen before the security gate.** The 21 false criticals from `.agents/update-backup/` and worktree copies wasted a scan cycle. A pre-gate cleanup step — removing known backup/cruft directories — would make the scan report actionable on first run.

### Patterns observed

1. **Conflict resolution `--ours` is lossy for structured files.** YAML lockfiles, TOML manifests, and version-carriers have different semantics from source code. Treating them identically during merge conflcts caused this regression.

2. **Transitive pre-release patches are a dependency health smell.** Research-keeper doesn't import `twisted` directly — it comes through `magic-wormhole` (peer-to-peer file transfer). When a transitive dep has a vulnerability with no stable patch, the project inherits release friction it didn't cause.

3. **Worktree sprawl amplifies noise.** Each active worktree had a copy of `.agents/update-backup/`. More worktrees = more scan findings for the same root cause. Automatic worktree cleanup after merge would prevent accumulation.
